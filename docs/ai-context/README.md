# Contexto do projeto

Este diretório é a referência rápida para pessoas e IAs. Ele evita que seja necessário ler todo o repositório para entender o produto, o estado atual e as decisões já tomadas.

## Leitura rápida

1. Ler `current-state.md` para saber em que ponto o projeto está.
2. Ler `product-vision.md` e `mvp-scope.md` para tarefas de produto, interface ou funcionalidades.
3. Ler `decisions.md` antes de propor tecnologias, arquitetura ou mudanças de escopo.
4. Ler `data-model.md` antes de tarefas de banco ou dados.
5. Ler `file-structure.md` antes de criar ou reorganizar arquivos.
6. Ler `build-plan.md` antes de iniciar uma funcionalidade do MVP.
7. Ler `validation-plan.md` antes de testar ou finalizar uma entrega.
8. Ler `release-security-plan.md` antes de publicar, alterar acesso ou realizar backup.
9. Ler `operations-evolution.md` para tarefas operacionais e planejamento pós-MVP.
10. Ler `architecture.md` antes de tarefas técnicas, de autenticação ou publicação.
11. Ler `roadmap.md` para planejar o próximo trabalho.
12. Consultar `change-log.md` e `activity-log.md` apenas quando o histórico for relevante.
13. Ler `funil-status-runbook.md` antes de migrar, ligar a flag ou planejar rollback do funil F1.
14. Ler `fila-cadencia-runbook.md` antes de migrar, ligar a flag ou planejar rollback da fila F2.
15. Ler `kit-whatsapp-runbook.md` antes de migrar, ligar a flag ou planejar rollback do kit WhatsApp F3.

## Regras de manutenção

- Manter todos os arquivos curtos, objetivos e em português.
- Registrar decisões que alterem produto, dados, arquitetura, segurança ou escopo.
- Atualizar o estado atual ao concluir cada etapa relevante.
- Registrar no changelog somente mudanças que afetam o projeto.
- Registrar no diário de atividades apenas trabalho relevante, bloqueios e próximos passos.
- Usar links para arquivos específicos em vez de duplicar informação.
